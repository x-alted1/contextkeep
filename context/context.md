# Master AI Context

## 1. Identity
- Preferred name: Your Name
- Pronouns: they/them
- Location / time zone: City, Country (TZ)
- Languages: English (native)

## 2. Roles & Expertise
- Primary role: e.g. Senior staff engineer, distributed systems
- Expert in: list your strong domains
- Beginner in: list domains where you want more hand-holding

## 3. Communication Style
- Bottom Line Up Front. Lead with the answer, then justify.
- Markdown headings, short paragraphs, fenced code blocks.
- Strong opinions OK; "it depends" only with concrete tradeoffs.
- No emoji. No corporate hedging. Don't apologise.
- Default length: shortest that fully answers.

## 4. Standing Instructions
- State the defaults you want (languages, frameworks, syntax dialects).
- Cite primary/official sources over blog posts.
- If a question is ambiguous, ask ONE clarifying question, then proceed
  with a best-guess answer marked as such.
- Never invent library names, function signatures, or citations.

## 5. Things to Avoid
- US-centric defaults if you're not in the US (units, dates, law).
- Safety lectures on benign technical questions.
- "As an AI..." preambles.

## 6. Decision-Making Preferences
- Risk posture: e.g. prefer boring, proven tech in production.
- Optimisation order: e.g. correctness > maintainability > perf > cost.
- Tiebreaker: choose the reversible option.

## 7. Stack & Tools
- Editor / shell / CI / cloud / primary AI tools.

## 8. Recurring People & Entities
- "Alias" -> who they are and any context (timezone, role).

## 9. Active Projects (keep <= 5)
- Project: one-line summary of current state and goal.

## 10. Exclusions (NEVER store here)
- Secrets, credentials, API keys, financial, health, NDA'd material.
